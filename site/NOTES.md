## Concept

KubeCompass's one idea is that a topology map should say how sure it is about each line. Sea charts
solved that long ago. The page is a **sheet of a nautical chart with its source diagram**.

### Reference

The Admiralty chart and its **source diagram / zones of confidence (ZOC)** panel: a small inset on a
paper chart that says, area by area, how the soundings were obtained (full survey, older lead-line
survey, reported, unsurveyed). Unsurveyed water is left explicitly blank and labelled, never filled
in. For the dark theme: the ECDIS (IHO S-52) day and night colour tables, where the same chart is
redrawn on a dark ground with lifted ink so it can be read at night. Honoured in:

- **Grid:** a single reading column of 62–66ch, set on the left of a wide sheet with a hairline
  neat line (the chart border) and a graduated edge, like the latitude scale. Section heads sit in
  the margin on desktop, like chart notes; inline on phone.
- **Type:** Literata (OFL) for reading, the way chart notes are set in a book roman; Atkinson
  Hyperlegible Mono (OFL) for every Kubernetes name, field path, label and value. Two families,
  self-hosted, Latin subset.
- **Colour:** chart paper (warm off-white) and black ink; one chart magenta for the one thing that
  matters on each sheet (the selected relationship, focus outlines are ink not magenta); a pale buff
  for the unsurveyed boundary. Night: S-52 style dark ground with lifted ink and a lifted magenta,
  each pair checked for AA. No gradients, glow, cards or chips.
- **Texture:** hairlines, a graduated border, hatching for the unavailable area. All SVG drawn for
  this page.

## Signature object: the source diagram of one demo graph

The graph KubeCompassCore builds for its own demo fixture, redrawn as a chart.

- **Data:** `site/data/demo-graph.json`, generated by `site/scripts/demo-graph.sh`, which compiles
  `site/tools/demo-graph/main.swift` together with `Sources/KubeCompassCore/*.swift` and runs
  `TopologyGraphBuilder.build` on the resources of
  `Tests/KubeCompassCoreTests/TopologyGraphTests.swift`
  `testOwnerChainPlacementServiceEndpointIngressStorageAndConfigEdges` (lines 19–30). No product
  code changed. The page says it is a redraw of that test fixture, not a capture of the app.
- **Content:** 12 nodes (11 resources in namespace `demo` plus the virtual control-plane boundary),
  18 edges: 11 Observed, 4 Declared, 2 Inferred (`selects`), and the control-plane boundary node
  tagged Unavailable with no edges drawn to it. Completeness `partial`, 2 unresolved references
  (counted, not named).
- **Line language (redundant with text, never colour alone):** Observed = solid ink line; Declared
  = long dash; Inferred = dotted; Unavailable = hatched area with the word "Unavailable" and no
  lines into it. Every edge also has a text label and an entry in the relationship list.
- **Plain layer:** the relationship list (HTML, from the same JSON): from → to, relationship,
  evidence level, source field, join rule, and the assumption where the core gives one. On phone
  (< 700 px) the list is the object; the map is behind a "Show the map" disclosure.
- **Signature motion (once, ~1.6 s, `no-preference` only):** the "survey pass": a thin scan line
  crosses the sheet left to right; Observed lines are inked as it passes, then Declared dashes,
  then Inferred dots, and last the Unavailable hatch is laid and labelled. No loop. Reduced motion
  and JS off show the finished sheet.
- **Micro-interactions (2–4):** (1) legend entries are toggle buttons (`aria-pressed`) that isolate
  one evidence level in the map and list; (2) focusing or hovering a node lights its edges and
  shows its relationships in a caption line; (3) hovering or focusing a list row highlights that
  edge in the map; (4) the selected edge shows its source field and join rule in a caption.
- **Real captures:** below the object, two tracked app captures from `docs/interface/evidence/`
  (`topology-map-control-plane.jpeg`, `topology-relationship-list.jpeg`), lazy, cropped, captioned
  as the app on a synthetic fixture, with alt text describing only what is shown.

## Copy (draft; voice per PLAYBOOK §1)

- h1: KubeCompass
- Lead: A Kubernetes client for the Mac. Its topology map says how it knows each line it draws.
- Sub: Every relationship is tagged Observed, Declared, Inferred or Unavailable. When an input is
  missing, the map says so instead of drawing it as complete.
- Status line: No published release yet. Build it from source on macOS 26 or later.
- Primary action: "Build from source" → README `#install`. Secondary: "Repository on GitHub".
- Object caption: Drawn from the graph KubeCompassCore builds for the demo fixture in its test
  suite. Not a screenshot.
- What a line means: the four levels, one sentence each, from `Sources/KubeCompassCore/TopologyGraph.swift`
  field values in the JSON (source field, join rule, assumption).
- What it cannot see: Traffic. Without a telemetry adapter traffic shows as unavailable. Selectors
  and Ingress backends are configuration, not proof of traffic (ADR 0001).
- How it runs: a bundled kubectl and your kubeconfig, so your existing auth plugins work. App
  Sandbox is off, because the app reads `~/.kube` and starts kubectl. The updater is off until a
  release feed exists.
- Status: no release yet; the build turns code signing off; Linux adapter runs on fixture data
  only; the README lists what is still unverified.
- Origin: derived from K-Dex by irfancen, MIT, provenance in UPSTREAM.md.
